# Phage Synergy Explorer

An interactive front end to a Bayesian Bliss model of phage-phage interaction.
It takes either a single phage pair typed by hand or a full screening table, and
it is deliberately agnostic about the naming, layout and size of that table.

Built with [Rhino](https://appsilon.github.io/rhino/).

## Files

```
app/main.R                 UI and server (the `app` module)
app/logic/data_input.R     reading tables, treatment discovery, dataset preparation
app/logic/bliss.R          deterministic Bliss arithmetic and the JAGS fit
app/logic/bliss_model.R    JAGS model string (bliss_zhao_n)
app/logic/postprocessing.R posterior summaries, calls, Bayes factor, convergence
app/logic/plots.R          interaction map, effect ladder, posterior figures
app/logic/mock_data.R      generator of the simulated example
app/static/example_mock.csv simulated example screen (not experimental data)
app/styles/main.scss       styles
tests/testthat/            unit tests, one file per script
```

## Run

```r
renv::restore()
rhino::build_sass()   # once, and after editing app/styles
shiny::runApp()       # from the project root
```

JAGS (<https://mcmc-jags.sourceforge.io>) is optional: without it the app still
produces point estimates, only the posterior fit is disabled.

## Deploy

```r
rsconnect::deployApp()
```

The hosted server must have the JAGS system library for the Bayesian fit.
shinyapps.io does not ship it, so there the app runs in point-estimate mode;
use a server where JAGS can be installed (Posit Connect, Shiny Server, Docker)
for the full model.

## Two ways in

**Quick pair.** Type a strain name, two phage names, and the effect of phage A
alone, phage B alone and the combination. Each field accepts one value or
several replicates separated by commas or spaces. Useful for a single
experiment, or for checking one pair from a paper.

**Data table.** Upload (`.csv`, `.tsv`, `.txt`, `.xlsx`, `.xls`, `.rds`,
`.RData`), paste a block copied from a spreadsheet, or load the built-in
simulated example (also downloadable as a template). Excel workbooks and
`.RData` files offer a sheet/object picker.

The example is generated by `make_mock_data()` in `app/logic/mock_data.R`: 8 strains x 3 replicates,
three phages (`PhiA`, `PhiB`, `PhiC`), their three pairs, the triple and a
`Nophage` control. Strains 01-03 are built with a positive deviation from Bliss
(synergy), 04-06 with none (additivity) and 07-08 with a negative one
(antagonism), so the app's output can be checked against a known answer.

Both paths go through the same engine, so the arithmetic, the threshold and the
model are identical whichever one is used.

## What "agnostic" means here

- **No fixed column names.** The strain and replicate columns are guessed from
  the header and can be overridden. Both are optional: without a strain column
  every row belongs to one sample; without a replicate column each row within a
  strain is treated as one replicate.
- **No fixed treatment names.** A column is read as a *combination* when its
  name splits into components that are themselves columns. `V1SA12+V1SA19`,
  `p1_p2`, `phageA:phageB` and `A|B` all work; the separator is detected from
  the header and can be overridden.
- **Any number of phages per combination.** `P1+P2+P3` is analysed exactly like
  a pair, through the generalised Bliss expectation.
- **Controls fall out on their own.** `Nophage`, `all_phages`, `control`,
  `blank` and friends are pre-selected in the "columns to ignore" list, and any
  column whose parts do not match single treatments is never read as a
  combination.
- **Wide or long.** One column per treatment, or one row per measurement with
  treatment/value columns.
- **Either scale.** Effects are fractions of growth suppressed; a table on a
  0-100 scale is detected and divided by 100.

## Outputs

Both figures are interactive: hover any point for its numbers, drag to zoom,
double-click to reset, and use the expand icon at the bottom right of the card
to fill the screen. They are also sized from the data rather than squeezed into
a fixed box, so a 25-strain screen gets 25 readable rows and the card scrolls.

- **Interaction map** - bubble matrix of strains against combinations, bubble
  size = observed combination effect, fill = interaction, on a divergent scale
  centred on zero. Choose what the colour shows (observed gap, posterior
  synergy effect, or the posterior probability of synergy) and whether strains
  are ordered alphabetically or by interaction strength. A single pair gets an
  effect-ladder plot instead.
- **Results** - one row per strain and combination: observed mean, Bliss
  expectation, gap, and, once the model is fitted, the posterior median, its
  95% credible interval, the posterior probabilities, the Bayes factor and the
  call. Sortable, with a filter box on every column.
- **Posterior** - forest plot of the synergy effect against the region of
  practical equivalence, with controls for which combinations to show, how many
  panels per row and how strains are ordered, plus the convergence table
  (R-hat, effective sample size).
- **Data** - the prepared table, with a note on what was detected, rescaled or
  clamped.
- **CSV / PNG export** - the results table, and whichever figure is on screen
  at a height matched to its contents.

## Decision rule

A gap between the observed combination effect and the Bliss expectation is only
called an interaction when it exceeds the *region of practical equivalence*
(ROPE), by default the median within-strain replicate standard deviation with a
floor of 0.05. A difference smaller than the assay's own noise is not an
interaction. The Bayesian call additionally requires the posterior to be at
least 95% (adjustable) sure of the category, otherwise the pair stays
*Inconclusive* rather than being forced into one.

## Model (Bayesian Bliss)

The app fits `bliss_zhao_n`, the replicate-level Bliss model generalised to
$n_p$ phages. For each bacterium $b$, each phage $k$ of the combination and
each replicate $r$:

- Single-phage effects are modelled on the probability scale through a
  logit-normal hierarchy:

$$
\operatorname{logit}(p_{k,b}) \sim \mathcal{N}(0, 0.16)
$$

- The Bliss expected effect is the complement of the survival product:

$$
\mu_b = 1 - \prod_{k=1}^{n_p} (1 - p_{k,b})
$$

  which for $n_p = 2$ is the familiar $p_{1,b} + p_{2,b} - p_{1,b}p_{2,b}$.

- A bacteria-specific deviation from Bliss is added on the logit scale:

$$
\delta_b \sim \mathcal{N}(0, \tau_{\delta}), \quad
\operatorname{logit}(p_{c,b}) = \operatorname{logit}(\mu_b) + \delta_b
$$

- The interaction effect reported by the model is:

$$
\mathrm{synergy}_b = p_{c,b} - \mu_b
$$

- Observation model for replicates:

$$
P_{k,b,r} \sim \text{Beta}(p_{k,b}\phi_s, (1-p_{k,b})\phi_s),
$$

$$
Y_{obs,b,r} \sim \text{Beta}(p_{c,b}\phi_c, (1-p_{c,b})\phi_c)
$$

- Main priors:

$$
\sigma_\delta \sim \mathcal{U}(0,2), \quad
tau_{\delta} = \sigma_\delta^{-2}, \quad
\phi_s \sim \Gamma(2,0.1), \quad
\phi_c \sim \Gamma(2,0.1)
$$

Interpretation:

- $\mathrm{synergy}_b > 0$: observed combination tends to be stronger than Bliss expectation (synergy)
- $\mathrm{synergy}_b < 0$: observed combination tends to be weaker than Bliss expectation (antagonism)

The Bayes factor divides the posterior odds of a relevant synergy by the prior
odds obtained by simulating the same priors forward, so the evidence is
reported separately from the prior.

### Why These Modeling Choices

- Bliss baseline:
	Bliss independence ($\mu_b = 1 - \prod_k (1 - p_{k,b})$) is a standard null model for non-interacting agents. It provides a biologically interpretable reference to classify synergy or antagonism.

- Logit parameterization for means:
	Modeling latent means on the logit scale keeps probabilities in $(0,1)$ after inverse-logit transformation and gives stable inference near boundaries.

- Replicate-level likelihood (Beta):
	Experimental effects are proportions bounded between 0 and 1. A Beta likelihood naturally matches this support and allows flexible variance through precision parameters.

- Separate precision terms ($\phi_s$, $\phi_c$):
	Single-phage and combination measurements can have different noise levels. Using separate precision parameters avoids forcing identical variability across assay contexts.

- Strain-specific deviation term ($\delta_b$):
	Adding $\delta_b$ on the logit scale captures bacteria-level departures from Bliss while preserving the probability scale for $p_{c,b}$.

- Hierarchical shrinkage across bacteria:
	Centering $\delta_b$ at zero with shared variance regularizes extreme estimates for bacteria with limited information, improving robustness. With a single strain there is nothing to share, so the deviation is shrunk by its prior alone: read a one-strain fit as a weak-evidence answer.

- Weakly informative priors:
	Priors are broad enough to let data dominate but still constrain implausible parameter values, which is useful for finite replicate counts and improves MCMC stability.

- Direct effect metric ($\mathrm{synergy}_b = p_{c,b} - \mu_b$):
	Reporting the difference on the probability scale gives an immediately interpretable magnitude of interaction for each bacteria.
